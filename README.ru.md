# Aurora Tasks

Быстрый анимированный список задач, который работает целиком в браузере. Аккаунта,
сервера и синхронизации нет — каждая задача живёт в `localStorage` вашего браузера, на
вашем же компьютере. Приложение для одного человека, который хочет спокойный,
удобный с клавиатуры список на день или неделю, а не командный трекер задач.

**Демо:** пока не опубликовано — ссылку сюда добавит DevOps, когда приложение будет
развёрнуто.

## Стек

| Выбор | Что | Почему |
|---|---|---|
| UI | React 19 + TypeScript (strict) | уже в репозитории |
| Сборка | Vite 8 | уже в репозитории |
| Стили | Tailwind CSS v4 поверх слоя CSS-токенов | утилиты быстрые, но любое значение всё равно обязано приходить из токена, а не быть захардкожено |
| Анимации | Framer Motion | уже в репозитории |
| Тесты | Vitest + Testing Library + jsdom | уже в репозитории |
| Данные | `localStorage`, без сервера | сервера нет по условию |

Новая runtime-зависимость не добавляется без причины, записанной в задаче, и ревью
TechLead/Security — см. `docs/ARCHITECTURE.md` §1. Это осознанно держит дерево
зависимостей маленьким (*boring technology*), а вместе с ним — и поверхность атаки.

## Как запустить

### Требования

- Node.js 24 или новее (проект собран и проверен на `v24.21.0`)
- npm (идёт вместе с Node.js)

### Установка

```bash
npm install
```

### Запуск локально

```bash
npm run dev
```

Поднимает dev-сервер Vite и печатает локальный адрес: `http://localhost:5173/todo-app/`.
Путь `/todo-app/` не опционален — приложение собрано с этим базовым путём (см.
`vite.config.ts`) и не смонтируется по голому корню. Откройте напечатанный адрес в
браузере; страница перезагружается при каждом изменении файла.

### Продуктовая сборка

```bash
npm run build
```

Запускает сборку TypeScript-проекта (`tsc -b`), затем продуктовую сборку Vite.
Результат — в `dist/`. Команда падает при любой ошибке типов, поэтому она же —
единственная авторитетная проверка типов перед релизом.

### Просмотр продуктовой сборки

```bash
npm run preview
```

Раздаёт собранную выше папку `dist/` по адресу `http://localhost:4173/todo-app/` — так
же, как приложение будет раздаваться после публикации DevOps. Полезно проверить
продуктовую сборку перед релизом, потому что `npm run dev` использует другой путь
сборки.

### Линт и проверка типов

```bash
npm run lint       # oxlint
npm run typecheck  # tsc -b, no emit
```

### Тесты

```bash
npm run test
```

Запускает набор Vitest один раз (без watch-режима) и печатает, сколько файлов и тестов
прошло. Это число меняется почти с каждым PR, поэтому здесь оно не фиксируется —
запустите команду, чтобы увидеть текущее состояние `main`.

Все четыре команды выше (`lint`, `typecheck`, `test`, `build`) — это же обязательные
проверки CI для каждого pull request, см. [Вклад в проект](#вклад-в-проект).

## Структура проекта

Полное описание и обоснование каждого решения — в
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Короткая версия:

```
src/
  domain/      чистый TypeScript, ни одного импорта React — модель задачи, операции над списком, фильтры, сроки
  storage/     обёртка над localStorage, валидация схемы, персист с задержкой
  state/       единственный reducer задач, React context/providers (задачи, тема, тосты)
  components/  презентационные блоки (Button, Checkbox, Menu, Toast, ...)
  features/    экранная логика, связывающая стор и компоненты (композер, тулбар, ...)
  layout/      каркас страницы, шапка, анимированный фон, плавающая кнопка
  lib/         мелкие хелперы, в основном React-хуки (debounce, фокус/закрытие, ...)
  styles/      слой токенов (`tokens.css`) и глобальный CSS (`base.css`)
  assets/      самостоятельно хостящиеся подрезки шрифтов (см. раздел «Шрифты» ниже)
```

Правило, которое делает структуру рабочей: `domain/` никогда не импортирует React, а
`components/` никогда не читает состояние приложения напрямую — компоненту, которому
нужен стор задач, место в `features/`, а не в `components/`. `ErrorBanner` (в
`components/`) — единственное осознанное исключение: он читает `useTaskStore`/`useToast`
напрямую, потому что кнопке экспорта нужен и живой список задач, и карантинная резервная
копия, которую хранит только `storage/` — см. комментарий в `ErrorBanner.tsx`. `lib/` —
это «мелкие хелперы», а не «независимое от фреймворка»: большая часть
(`useDismissable`, `useDebouncedValue`, `useMediaQuery`, ...) — React-хуки; лишь
несколько модулей там (`cn`, `dismissStack`, ...) вообще не импортируют React. Полное
обоснование — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §2, а
правила безопасности (что нельзя превращать текст пользователя в HTML, как обязана
работать подсветка поиска и так далее) — в
[`docs/CODE-RULES.md`](docs/CODE-RULES.md). Полный визуальный контракт — токены,
состояния компонентов, состояния экранов, критерии приёмки — в
[`docs/design-spec.md`](docs/design-spec.md).

Два из этих критериев приёмки — внутренние контракты по вёрстке и типографике, а не
функции продукта, поэтому здесь каждому посвящена одна строка: `AppHeader` и `main`
лежат в одной центрированной колонке (`--layout-content-max`), а у самой шапки нет ни
фона, ни грани, ни `sticky` (критерий 34); моноширинный текст (счётчики сегментов,
таблица горячих клавиш) всегда имеет вес 400 и ставится единственным классом
`.text-mono-num` — прямой `font-family: var(--font-mono)` в разметке запрещён
(критерий 35).

## Как пользоваться

- **Добавить задачу.** Введите текст в поле композера и нажмите `Enter` (на мобильном —
  кнопку `+`/FAB). Приоритет (нет/низкий/средний/высокий) и срок можно задать на том же
  поле перед отправкой.
- **Изменить существующую задачу.** Откройте редактор кнопкой правки, двойным кликом по
  строке, пунктом «Изменить» в меню строки или клавишей `E`, когда строка в фокусе.
  Редактор — единственное место, где текст, приоритет и срок меняются все три сразу;
  `Enter` сохраняет, пока фокус в текстовом поле, `Esc` отменяет, клик снаружи
  сохраняет. Пустой текст отменяет правку, а не удаляет задачу.
  На десктопе есть более быстрый путь для двух оставшихся полей: клик по чипу
  приоритета или срока прямо в строке открывает тот же попап и применяет новое значение
  сразу, без отдельного шага сохранения. На мобильном редактор — это bottom sheet, а не
  строка на месте, и чипы в строке там не кликабельны — правка приоритета и срока на
  мобильном всегда идёт через этот лист.
- **Фильтры и поиск.** Сегменты «Все» / «Активные» / «Выполненные» и поле поиска сужают
  список; они работают вместе, и у каждого сегмента — живой счётчик.
- **Изменить порядок задач.** Перетащите строку за её ручку или сделайте то же с
  клавиатуры: сфокусируйте строку, нажмите `Space`, чтобы «поднять» её, `↑`/`↓`, чтобы
  переместить, `Space` снова, чтобы «опустить». На мобильном постоянной ручки
  перетаскивания нет — откройте меню строки и выберите «Переместить» для тех же
  кнопок вверх/вниз без мыши. `Ctrl`/`Cmd`+`↑`/`↓` на сфокусированной строке также
  двигает её на шаг на любом устройстве, без входа в этот режим.
- **Отменить удаление.** Удаление задачи показывает тост с кнопкой «Вернуть» на
  несколько секунд; то же самое делает глобальная клавиша `Ctrl`/`Cmd+Z`.
- **Переключить тему.** Переключатель темы — в шапке; выбор сохраняется (`aurora.theme`)
  и восстанавливается при перезагрузке, до первой отрисовки, без вспышки неправильной
  темы.
- **Горячие клавиши.** Нажмите `?` или кнопку горячих клавиш в шапке, чтобы увидеть
  внутри приложения ту же таблицу:

  | Клавиша | Действие |
  |---|---|
  | `N` | Новая задача |
  | `/` | Фокус в поле поиска |
  | `1` `2` `3` | Переключить фильтр (Все / Активные / Выполненные) |
  | `?` | Открыть шпаргалку горячих клавиш |
  | `Esc` | Закрыть / отменить / очистить — что открыто |
  | `↑` `↓` | Переход фокуса между строками |
  | `Space` | Отметить сфокусированную задачу выполненной |
  | `E` | Править сфокусированную задачу (текст, приоритет и срок) |
  | `Delete` / `Backspace` | Удалить сфокусированную задачу |
  | `Ctrl`/`Cmd`+`Z` | Вернуть последнюю удалённую |
  | `Ctrl`/`Cmd`+`↑`/`↓` | Переместить сфокусированную строку на шаг |

  (источник: `docs/design-spec.md` §6.3 — отдельных горячих клавиш на приоритет и срок
  нет сознательно: редактор по клавише `E` уже даёт доступ к обоим полям.)

## Данные

Всё хранится в `localStorage` браузера, в трёх ключах:

- `aurora.tasks.v1` — список задач, как `{ "version": 1, "tasks": Task[] }`.
- `aurora.theme` — выбранная тема, `"light"` или `"dark"`.
- `aurora.tasks.v1.corrupted` — карантинная копия сырых байтов `aurora.tasks.v1`,
  записывается только когда чтение находит их нечитаемыми (см. ниже).

**Сервера и аккаунта нет.** Из браузера ничего не уходит: сетевых запросов в приложении
нет вообще. Очистка данных сайта (или `localStorage`) в этом браузере удаляет ваши
задачи навсегда — восстановить их не из чего.

Список читается один раз, синхронно, до первой отрисовки, и записывается обратно с
задержкой 250 мс после каждого изменения.

**Если сохранённые данные нечитаемы** (битый JSON, правка руками, запись другой версией
приложения), приложение пытается их сохранить, но это не гарантия. При чтении оно
пытается скопировать неразобранные байты в третий ключ, `aurora.tasks.v1.corrupted`, до
того, как что-либо ещё коснётся `aurora.tasks.v1` — но и эта копия может не получиться
(квота хранилища, ограничения приватного режима, недоступный backend), и тогда попытка
только логируется в разработке, а исходные байты пропадают. Приложение запускается с
пустым списком в памяти и показывает баннер ошибки, объясняющий, что сохранённые данные
не удалось прочитать. Кнопка экспорта на баннере скачивает карантинную копию только если
она действительно была сохранена и до неё можно достучаться; иначе показывается тост
(«Выгружать нечего: повреждённые данные не сохранились.») и файл не создаётся.

## Шрифты

Два шрифта (`Inter` переменный и `JetBrains Mono`, только вес 400) идут как подрезанные
файлы `.woff2`, закоммиченные в `src/assets/fonts/`, а не загружаются с CDN — политика
зависимостей этого репозитория запрещает сторонние CDN для скриптов и шрифтов (см.
[`docs/CODE-RULES.md`](docs/CODE-RULES.md) §1: это одновременно запрос к третьей стороне
на каждый визит и внешний код/контент в собственном origin приложения).

Именно поэтому сборке никогда не нужен доступ в сеть: всё, что она раздаёт, уже лежит в
репозитории. Чтобы пересобрать подрезки из исходных релизов шрифтов (нужно только если
меняется покрытие символов), запустите `scripts/subset-fonts.sh` — он принимает исходные
файлы `.ttf` аргументами, а в заголовке скрипта зафиксированы точный исходный релиз и
`sha256` для каждого файла, а также версии `fonttools`/`brotli`, нужные для
побайтово воспроизводимой пересборки.

## Вклад в проект

- `main` всегда зелёная: прямых коммитов в `main` нет.
- Одна ветка на задачу, с номером тикета в имени, например `feat/FELA-15-task-list`,
  `fix/FELA-65-composer-focus`, `docs/FELA-24-readme`.
- Коммиты — [Conventional Commits](https://www.conventionalcommits.org/), на английском,
  с номером задачи: `feat: add task list reducer (FELA-9)`.
- Любое изменение идёт через pull request. CI обязан быть зелёным: `lint`, `typecheck`,
  `test` и `build` (см. [Как запустить](#как-запустить) — это ровно те же четыре
  команды `npm run` выше).
- Автор PR не вливает свой же PR. Проверка `review-ack` держит PR красным, пока ревьюер
  не оставит комментарий, первая строка которого — ровно `/merge-ok` (опционально
  `/merge-ok <sha>`) на текущем коммите; любой новый push сбрасывает её. Механика — в
  `.github/workflows/review-ack.yml`, полный чек-лист PR, включая чек-лист безопасности
  из [`docs/CODE-RULES.md`](docs/CODE-RULES.md), — в
  `.github/pull_request_template.md`.

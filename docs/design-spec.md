# Design spec — Aurora Tasks

Версия 1.6 · концепт **A (Aurora Glass)** принят как решение по умолчанию (см. документ `concepts`).
Имена токенов и компонентов — английские, их берут в код как есть. Прозаические описания — русские.

Эталон реализации: вложения `concept-a.html` (главный экран, обе темы, 1440 и 390), `concept-a-states.html` (пустые состояния, скелет, ошибка, длинный текст) и `concept-a-edit.html` (правка приоритета и срока). Это не картинки, а рабочий HTML с тем же слоем токенов — верстальщику можно открыть и измерить.

**Что изменилось в 1.6** (по открытому вопросу FELA-81):
1. Раздел 3.5 задавал высоту `Button` одним числом на размер (`sm` 32 · `md` 40 · `lg` 48), без вьюпорта. Раздел 7 при этом требует на мобайле ≥44×44. Для `sm` расхождение закрыли в FELA-76, для `md` оно оставалось: 40 px и на десктопе, и на телефоне. Решение зафиксировано: **на мобайле все размеры `Button` ≥44**. Числа по вьюпортам выписаны в 3.5.
2. Почему не исключение для `md`: единственное место, где `md` сейчас живёт, — это `ConfirmDialog` (3.16), то есть обе кнопки массового удаления. На мобайле это и есть та цель, которой нельзя промахнуться, а не редкий случай. Про «`md` на мобайле почти не используется» — это было верно на момент FELA-76 по числу вызовов, но не по весу сценария.
3. В 7 добавлено, что кнопка добирает 44 px собственной высотой, а не зазором.
4. Добавлен критерий приёмки 37.

Нумерация разделов, компонентов и критериев 1–36 в 1.6 не сдвинута.

**Что изменилось в 1.5** (по находке разработки из FELA-72):
1. Обязательный блок 2.7 перечислял шесть классов, и `.toast` среди них не было — при этом в коде `backdrop-filter` стоит ровно на одном компоненте, на `Toast`. То есть фолбэк не покрывал единственную поверхность, которая его реально требует. Решение зафиксировано: **`.toast` входит в блок 2.7 и получает `--color-surface-2-solid`**, а не `--color-surface-1-solid` — тост по 3.17 стоит на `--color-surface-2`, и подложка от `surface-1` сменила бы ему уровень поверхности и убрала бы тоновую границу со строкой списка под ним. Размытие у тоста остаётся.
2. В 3.17 выписан фон, размытие и требование держать класс `.toast` на корневом элементе компонента.
3. В 2.7 внесена вторая размывающая поверхность, которой в спеке не было: полоса тулбара `.toolbar-sticky.is-stuck` (3.9). Она появилась в коде вместе с `--blur-sticky` и уже носила свой фолбэк, но в обязательном списке не значилась — то есть блок 2.7 расходился с кодом в обе стороны сразу. Токен `--blur-sticky: 16px` тоже выписан.
4. Добавлен критерий приёмки 36 — двусторонняя проверка: мёртвых крючков в блоке нет и забытых размывающих поверхностей нет.

Нумерация разделов, компонентов и критериев 1–35 в 1.5 не сдвинута.

**Что изменилось в 1.4** (по вопросу разработки из FELA-46):
1. Таблица 2.5 задаёт веса 500 / 550 / 600 для `text-caption` / `text-label` / `text-micro`. Эти веса выбирались под Inter. JetBrains Mono лежит в репозитории одним статическим весом 400, поэтому любой моноширинный счётчик в этих токенах получал от браузера синтетический жирный — размазанный контур вместо настоящего начертания. Решение зафиксировано: **моно всегда 400**, вес берётся не из текстового токена. Правило и способ его записи — в 2.5, цвета счётчика в сегменте — в 3.9.
2. Веса в самих токенах `text-caption` / `text-label` / `text-micro` **не меняются** — они продолжают работать для Inter. Переменный файл JetBrains Mono не берём.
3. Добавлен критерий приёмки 35.

Нумерация разделов, компонентов и критериев 1–34 в 1.4 не сдвинута.

Спека не проговаривала внутреннюю геометрию `AppHeader`, и в каркасе шапка растянулась во всю ширину окна, а контент остался колонкой по центру — вордмарк оказался на `x = 24`, заголовок героя на `x = 364`. Нумерация разделов, компонентов и критериев 1–33 в 1.3 не сдвинута.

## 1. Продуктовые решения, влияющие на UI

Фиксирую здесь, чтобы разработка не доугадывала.

| Вопрос | Решение | Почему |
|---|---|---|
| Порядок списка | Только ручной (drag & drop). Автосортировок по сроку/приоритету нет | Два источника порядка конфликтуют; ручной порядок — это то, что просили (Occam's Razor) |
| Выполненные | Уезжают в отдельную секцию `Выполнено` внизу, порядок — по времени выполнения, новые сверху | Активный список не замусоривается, но прогресс виден (Zeigarnik) |
| Приоритет | 4 состояния: `none` (по умолчанию) / `low` / `medium` / `high`. При `none` чип не рисуется | Не заставляем выбирать на каждом добавлении (Hick's Law) |
| Срок | Только дата, без времени. Необязателен | В макете на карточке видно «Сегодня, 15:00» — **это не реализуем**, время вне объёма |
| Правка приоритета и срока | Основной путь — `TaskEditor` (3.11a), он же «Изменить» в меню. Быстрый путь — клик по чипу в строке, **только десктоп**, применяется сразу | Один предсказуемый путь на обоих вьюпортах + прямая манипуляция там, где хватает размера цели |
| Удаление одной задачи | Без диалога: сразу удаляем + тост `Undo` 6 с + `Ctrl/Cmd+Z` | Forgiveness важнее подтверждений; диалог на каждое удаление — трение |
| Удаление всех выполненных | Модальный `ConfirmDialog` с числом | Массовое и необратимое действие |
| Отметка «выполнено» | Без тоста, без подтверждения | Снимается одним кликом, тост был бы шумом |
| Поиск | По тексту задачи, внутри текущего фильтра, debounce 180 мс, подсветка `<mark>` | |
| Хранилище | `localStorage`, ключ `aurora.tasks.v1`, запись с debounce 250 мс | Сервера нет по условию |
| Тема | Старт от `prefers-color-scheme`, переключатель сохраняет выбор в `aurora.theme` | |

Тёмных паттернов в спеке нет и быть не должно: удаление не прячем, «Отмена» не окрашиваем в вину, счётчик выполненного не используем для давления.

Контрасты посчитаны по формуле WCAG 2.1 для пары «цвет текста на `--color-surface-1-solid`» (для `--color-control-border` — граница против той же поверхности). Значения проверяет автотест из критериев приёмки, а не глаз.

**Блик скелетона всегда светлее подложки — в обеих темах.** В тёмной теме это получается само: `--skeleton-shine` там белый с бо́льшей альфой, чем `--skeleton-base`. В светлой теме чернила те же, поэтому **альфа у `shine` меньше, чем у `base`** — иначе полоса поедет тёмной и скелет будет читаться как дефект. Градиент один и тот же: `linear-gradient(90deg, var(--skeleton-base), var(--skeleton-shine), var(--skeleton-base))`, параметры анимации — в 3.19 и в таблице анимаций.
При `prefers-reduced-motion: reduce` остаётся только `--skeleton-base`, поэтому он обязан быть виден сам по себе: 1.29:1 к `--color-surface-1-solid` (`#FFFFFF`) — это уровень обычного светлого плейсхолдера, заметно, но не похоже на реальную карточку. Пара base/shine в светлой теме отличается на 1.19:1 — столько же, сколько в тёмной (1.21:1), то есть блик читается одинаково в обеих темах.

**Что светлая тема не переопределяет намеренно.** `--color-accent`, `--color-accent-hover`, `--color-accent-active`, `--color-accent-contrast`, а также `--gradient-accent` и `--gradient-accent-soft`: акцент в продукте один и тот же в обеих темах, наследование здесь — решение, а не пропуск. Нецветные токены (spacing, typography, radii, motion, layout, z-index) от темы не зависят и тоже не повторяются; их мобильные значения живут в медиазапросе. Всё остальное цветовое обязано быть в светлом блоке явно: если цветовой токен там не найден — это баг, а не решение.

### 2.3 Gradient — правила использования

```
--gradient-accent:      linear-gradient(135deg,#7C5CF8 0%,#8B5CF6 42%,#06B6D4 100%)
--gradient-accent-soft: linear-gradient(135deg,rgba(124,92,248,.16),rgba(6,182,212,.14))
```

**Запрещено** класть текст на `--gradient-accent`: на циановом конце белый даёт 2.45:1. Разрешённые места: фон `AuroraBackground`, заливка `ProgressRing`, фон отмеченного `Checkbox` (там галочка — иконка 2 px stroke, не текст, и дублируется `aria-checked`), кружок `+` в `Composer` и `Fab` (иконка, не текст), подложка индикатора drop.
Кнопки с подписью — всегда сплошной `--color-accent`.

### 2.4 Spacing — шаг 4 px

`--space-1` 4 · `--space-2` 8 · `--space-3` 12 · `--space-4` 16 · `--space-5` 20 · `--space-6` 24 · `--space-8` 32 · `--space-10` 40 · `--space-12` 48 · `--space-16` 64 · `--space-20` 80

#### Вес моноширинного текста *(добавлено в v1.4, вопрос FELA-46)*

Веса в таблице выше выбраны под Inter: на 11–13 px гротеск нужно слегка утяжелять, иначе мелкая подпись рассыпается. Моно этого не требует — у JetBrains Mono штрих плотнее и знаки шире расставлены, на тех же кеглях 400 читается не светлее, чем Inter 400–500.

Правило: **моноширинный текст всегда `font-weight: 400`.** Вес из `text-caption` / `text-label` / `text-micro` на него не распространяется. В файле есть только 400; любой другой вес браузер подделывает — обводит контур сам, и на 11–13 px цифра заплывает.

В код это уходит **одним классом, а не правкой токенов**. Веса `text-caption` / `text-label` / `text-micro` остаются 500 / 550 / 600 — их носит Inter, и обнулять их до 400 нельзя, иначе просядет вся мелкая иерархия.

```css
/* Единственная точка входа в моно. Прямой font-family: var(--font-mono) без
 * этого класса в разметке запрещён. */
.text-mono-num {
  font-family: var(--font-mono);
  font-weight: var(--font-mono--font-weight); /* 400 — иного в файле нет */
  font-variant-numeric: tabular-nums;
}
```

Новый токен: `--font-mono--font-weight: 400`. Он существует, чтобы вес имел имя и ссылку на причину, а не висел магической четвёркой в классе.

Размер, интерлиньяж и трекинг моно **берёт у своего текстового токена** — меняется только вес. Счётчик сегмента: `text-caption` + `.text-mono-num`. Счётчик символов `Composer`: `text-caption` + `.text-mono-num`. `kbd`: `text-caption` + `.text-mono-num`.

`tabular-nums` здесь не украшение, а причина, по которой моно вообще взяли: ширина счётчика не должна дёргаться при 9 → 10. Поэтому класс всегда ставит три свойства разом — моно без `tabular-nums` или с чужим весом считается ошибкой вёрстки.

Моно никогда не набирает прозу и никогда не бывает жирным. Если в макете понадобился акцентный моно — это ошибка макета, а не повод тянуть переменный файл.

| Token | dark | light |
|---|---|---|
| `--shadow-xs` | `0 1px 2px rgba(3,3,10,.30)` | `0 1px 2px rgba(17,17,34,.05)` |
| `--shadow-sm` | `0 2px 8px rgba(3,3,10,.34)` | `0 2px 8px rgba(17,17,34,.07)` |
| `--shadow-md` | `0 8px 24px -4px rgba(3,3,10,.42)` | `0 10px 28px -6px rgba(17,17,34,.11)` |
| `--shadow-lg` | `0 24px 64px -12px rgba(3,3,10,.56)` | `0 26px 64px -14px rgba(17,17,34,.16)` |
| `--shadow-glow-accent` | `0 0 0 1px rgba(124,92,248,.45), 0 8px 32px -8px rgba(124,92,248,.45)` | `0 0 0 1px rgba(109,69,240,.35), 0 8px 28px -10px rgba(109,69,240,.35)` |
| `--shadow-drag` | `0 18px 44px -8px rgba(3,3,10,.60)` | `0 18px 44px -10px rgba(17,17,34,.22)` |

`--blur-surface: 20px` (поверхности), `--blur-aurora: 90px` (пятна сияния), `--blur-sticky: 16px` (полоса тулбара в состоянии `.is-stuck`, 3.9 — у неё своё значение, не `--blur-surface`).

Обязательный фолбэк:

```css
@supports not (backdrop-filter: blur(1px)) {
  .composer, .task-row, .search-field, .segmented-control, .icon-button, .progress-ring {
    background: var(--color-surface-1-solid);
  }
  /* Тост по 3.17 стоит на --color-surface-2: подложка обязана сохранить уровень
     поверхности, иначе тост сравняется по тону со строкой списка под ним. */
  .toast {
    background: var(--color-surface-2-solid);
  }
  /* Полоса тулбара (3.9): размывает только в .is-stuck, и вместе с размытием
     снимается маска-растушёвка — без blur она читается как обрезанный край. */
  .toolbar-sticky.is-stuck {
    background-color: var(--color-surface-1-solid);
    -webkit-mask-image: none;
    mask-image: none;
  }
}
```

Правило, по которому этот список пополняется: **класс попадает сюда тогда и только тогда, когда элемент применяет `backdrop-filter`.** Если компонент получает размытие — его класс добавляется в блок в той же правке; если размытие снимают — класс убирают. Подложка берётся того же уровня, что и полупрозрачный фон компонента: `surface-1` → `--color-surface-1-solid`, `surface-2` → `--color-surface-2-solid`. Сам класс обязан висеть на том же элементе, на котором стоит `backdrop-filter`, иначе фолбэк молча не срабатывает.

### 2.8 Motion

`--duration-instant` 80ms · `--duration-fast` 140ms · `--duration-base` 200ms · `--duration-slow` 320ms · `--duration-slower` 480ms

`--ease-standard` `cubic-bezier(.2,0,0,1)` · `--ease-out-soft` `cubic-bezier(.16,1,.3,1)` · `--ease-in-fast` `cubic-bezier(.4,0,1,1)` · `--ease-spring` `cubic-bezier(.34,1.56,.64,1)`

### 2.9 Layout & z-index

## 3. Components

Список закрытый. Нужен новый компонент — это предложение в систему, с обоснованием, а не тихая импровизация.

### 3.1 `AppShell`
Контейнер: `AuroraBackground` → `AppHeader` → `main` → `ToastViewport`.

**Колонка одна на всё приложение.** `AppHeader` и `main` — два одинаковых центрированных бокса `--layout-content-max` с одинаковым гаттером. Левый и правый края их содержимого совпадают пиксель в пиксель; второй вертикальной оси в макете нет. Так устроен эталон `concept-a.html` (`.header` и `main` там несут один и тот же `max-width` + `margin: 0 auto` + `padding-inline`), так это и реализуем.

`main`: гаттер по бокам, сверху `--space-8`, снизу `--space-20` (мобайл: `--space-5` сверху, 120 px снизу — под `Fab` и тост).

`AuroraBackground` — единственное, что идёт во всю ширину окна: он `fixed` и лежит под колонкой.

**Полосы у шапки нет.** Шапка не `sticky`, фона и нижней грани не имеет — на анимированном сиянии любая полупрозрачная полоса читается как грязный прямоугольник (та же причина, по которой `.is-stuck` у тулбара в 3.9 включается только после скролла). Единственная sticky-полоса в продукте — тулбар.
Если шапке когда-нибудь понадобится фон или грань, фон кладётся на **во всю ширину окна** внешним слоем, а содержимое остаётся в том же боксе колонки: full-bleed подложка, inset-содержимое. Это предложение в систему, а не правка на месте.

### 3.2 `AuroraBackground`
Три размытых круга (`--color-aurora-1..3`), `position: fixed`, `pointer-events: none`, поверх — зерно 4 px на `--color-surface-border` c `opacity .5`.
Анимация `aurora-drift`: `translate` ±40 px, 24 s, `ease-in-out`, `alternate`, бесконечно. При `prefers-reduced-motion: reduce` — выключена полностью (статичная композиция).
Состояния: нет.

### 3.3 `AppHeader`
Слева `wordmark`, справа `IconButton` «горячие клавиши» и `ThemeToggle`. Высота — `--layout-header-h`.

**Геометрия.** Содержимое лежит в боксе колонки из 2.9: `max-width: var(--layout-content-max)`, `margin-inline: auto`, `padding-inline: гаттер`, `justify-content: space-between`, зазор между правыми кнопками `--space-2`.
Контрольные числа на 1440×900: левый край вордмарка `x = 364` — ровно там же, где эйбрау и заголовок `Сегодня`; правый край внешней `IconButton` `x = 1076` — ровно там же, где правый край строки задачи. На 390×844: `16` и `374`.
Правую кнопку вешаем **границей кнопки** на 1076, а не глифом. Оптический выступ (вынести кнопку на отрицательный margin, чтобы с краем колонки сошёлся глиф) рассматривался и отклонён: кольцо фокуса и цель 40×40 тогда вылезают за колонку и ломают ту самую сетку, ради которой всё затевалось. Глиф уходит внутрь на 10 px — это зазор кнопки, он читается как поля, а не как сбой.

**Почему по колонке, а не во всю ширину.** Вордмарк, заголовок дня, `Composer`, тулбар и список — одна смысловая группа, и общая левая грань — её дешёвый носитель (Gestalt: Uniform Connectedness, Common Region). Вордмарк у края окна даёт третью вертикальную ось на экране, где содержательных осей две, и на 1440 между ним и заголовком получается 340 px пустоты без причины — глаз читает это как недоделанную вёрстку, а не как приём. Выигрыша нет: шапка ничего не держит по краям, полосы у неё нет.

**Wordmark.** Точка 22×22 с заливкой `--gradient-accent` и `--shadow-glow-accent`, зазор `--space-3`, подпись `AURORA · TASKS` — `text-label`, weight 650, tracking `+.02em`, цвет `--color-text-primary`. Точка декоративна (`aria-hidden`), смысл несёт подпись. Это не ссылка и не кнопка: экран один, навигации нет — кликабельный логотип был бы обещанием без адресата.

Состояния: нет.

### 3.4 `ThemeToggle`
Кнопка-иконка, переключает light ⇄ dark. Стартовое значение — `prefers-color-scheme`, выбор сохраняется.
Состояния: default, hover, focus-visible, active.
Доступность: `aria-pressed` не подходит (две равноправные темы) — используем `aria-label` «Тёмная тема» / «Светлая тема», описывающий **текущую** тему, и `title` с тем же текстом. Смена темы объявляется в `LiveRegion`.

### 3.5 `Button`
Варианты: `primary` (заливка `--color-accent`, текст `--color-accent-contrast`), `secondary` (прозрачная, грань `--color-surface-border-strong`), `ghost` (без грани), `danger` (заливка `--color-danger`, текст подбирается до 4.5:1).
Размеры — высота, десктоп / мобайл: `sm` 32 / 44 · `md` 40 / 44 · `lg` 48 / 48. Граница одна — брейкпоинт `sm:` 640 px, кнопка растёт снизу вверх (`h-11 sm:h-8` у `sm`, `h-11 sm:h-10` у `md`), тем же приёмом, что `Checkbox` (3.10) и `IconButton` (3.6). Горизонтальный паддинг от вьюпорта не зависит: `sm` 12 · `md` 16 · `lg` 20. Радиус `--radius-sm`, подпись `text-label`.

### 3.6 `IconButton`
40×40 десктоп, 44×44 мобайл. Обязателен `aria-label`. Те же состояния, что у `Button`.

### 3.7 `Composer`
Главное поле ввода новой задачи. Стеклянная панель `--radius-xl`, слева градиентная кнопка `+` 40 px, поле `text-body-lg`, справа `PrioritySelect` и `DueDatePicker` в виде чипов.
Состояния: `empty` (плейсхолдер «Что нужно сделать?») · `focused` (`--shadow-glow-accent`, граница прозрачная) · `filled` · `submitting` · `error` (пустая строка или >500 символов: подпись ошибки под полем, `aria-describedby`, граница `--color-danger`).
Поведение: `Enter` — добавить и оставить фокус в поле (серия задач подряд); `Shift+Enter` — перенос строки; `Esc` — очистить. После добавления чипы приоритета и срока **сбрасываются** — иначе пользователь незаметно наставит один приоритет всем.
Лимит: 500 символов, счётчик появляется с 450-го, не раньше.
Мобайл: `Composer` скрыт, его роль берёт `Fab` → bottom sheet с тем же составом.

### 3.8 `SearchField`
Высота 40 (мобайл 44), иконка лупы, `kbd` подсказка `/`, кнопка очистки при непустом значении.
Состояния: empty · focused · filled · `filled + no results`.
Debounce 180 мс. Число найденного уходит в `LiveRegion`: «Найдено 3 задачи».

### 3.9 `SegmentedControl` — фильтры
Три сегмента: `Все` / `Активные` / `Готовые`, у каждого счётчик моноширинным.
Счётчик — `text-caption` + `.text-mono-num` (2.5): 12/16, трекинг +0.02em, вес 400, `tabular-nums`. Отступ от подписи — `--space-2`.
Цвет счётчика *(уточнено в v1.4)*: в невыбранном сегменте `--color-text-secondary`, в выбранном `--color-text-primary`, при нуле `--color-text-tertiary`. Подпись сегмента остаётся `text-label` (13/550, Inter). Счётчик намеренно легче подписи: имя фильтра — то, на что нажимают, число — справка при нём. Поднимать счётчик до веса подписи не нужно; разницу держит цвет, а не вес.
Разметка `role="tablist"`, сегменты `role="tab"` + `aria-selected`, панель списка `role="tabpanel"`. Roving tabindex: Tab входит в группу один раз, ←/→ переключают, Home/End — края.
Состояния сегмента: default · hover · selected · focus-visible · `empty` (счётчик 0).
Про `empty` отдельно, потому что на этом легко ошибиться: это **только визуальное** состояние — счётчик приглушается до `--color-text-tertiary`, сам сегмент остаётся кликабельным и фокусируемым. Атрибуты `disabled` и `aria-disabled` на сегментах **запрещены**: пустой фильтр ведёт на осмысленный `EmptyState`, а не в тупик. Состояния `disabled` у `SegmentedControl` не существует.
Индикатор выделения едет между сегментами, не телепортируется.

### 3.11 `TaskRow`
Состав: `DragHandle` · `Checkbox` · тело (заголовок + мета-чипы) · действия (`edit`, `more`).

### 3.11a `TaskEditor` *(добавлено в v1.1)*
Режим правки существующей задачи. Это не отдельный экран, а состояние `editing` у `TaskRow`: строка на месте раскрывается в редактор, список не перестраивается.

Это **единственное место, где меняются все три поля задачи сразу**, и единственный путь правки приоритета и срока на мобайле.
Переиспользует без изменений: `PrioritySelect` (3.12) и `DueDatePicker` (3.13) из `Composer`, `Button` (3.5). Новых токенов не вводит.
Состояния: `open` · `dirty` (появляется «Сохранить» в активном виде; без изменений кнопка остаётся, но сохранение — no-op) · `error` (пусто или >500) · `saving` (только если запись в хранилище дала сбой — тогда `ErrorBanner`, редактор не закрывается и текст не теряется).

Закрывается: `Enter` (только пока фокус в `textarea`) сохраняет · `Esc` отменяет · клик снаружи сохраняет · пустой текст = отмена, не удаление.
Мобайл: вместо инлайн-редактора — bottom sheet с тем же составом; заголовок `Изменить задачу`, поля `Приоритет` и `Срок` строками по 48 px с чипом-значением справа, кнопки 48 px (`Отмена` слева, `Сохранить` справа — платформенная конвенция для листов; на десктопе наоборот, первичная первой — это осознанно, а не расхождение).
Макет: `concept-a-edit.html`, скриншоты `edit-dark-1440.png`, `edit-light-1440.png`, `edit-dark-390.png`.

### 3.12 `PriorityChip` / `PrioritySelect`
Три видимых уровня + «без приоритета» (чип отсутствует). Каждый уровень несёт **три** канала: глиф (`▲` high, `■` medium, `▼` low), цвет и подпись. Цвет никогда не единственный признак.
`PrioritySelect` — `Menu` из четырёх пунктов с теми же глифами, текущее значение помечено галочкой. Используется в трёх местах: `Composer`, `TaskEditor`, и как быстрый путь прямо из строки (см. ниже).
Состояния чипа: `static` · `interactive` (hover, focus-visible, open) · `empty` (пунктирная граница, подпись «Приоритет» — только в `TaskEditor` и в быстром пути на десктопе).
**Где чип интерактивен** *(уточнено в v1.1)*:

| Место | Десктоп | Мобайл |
|---|---|---|
| `Composer` | interactive | interactive (в bottom sheet) |
| `TaskEditor` | interactive | interactive |
| `TaskRow`, обычный вид | **interactive** — клик открывает `PrioritySelect` прямо из строки | **static** |

Мобильный `static` — не экономия, а следствие двух ограничений: чип 24 px не дотягивает до цели 44×44, а соседние чипы стоят вплотную, поэтому послабление WCAG 2.5.8 по зазору не применимо; плюс горизонтальный свайп строки перехватывал бы нажатие. Правка приоритета на мобайле идёт через `TaskEditor`.
Быстрый путь на десктопе: изменение применяется **сразу**, без «Сохранить», и уходит в `LiveRegion` («Приоритет: средний»). Тоста нет — действие обратимо повторным выбором. Чип в открытом состоянии — `--gradient-accent-soft` + граница `--color-accent-text`.

### 3.13 `DueDateChip` / `DueDatePicker`
Формат подписи: `Сегодня` · `Завтра` · `Пт, 24 окт` · `12 янв 2027` (если другой год) · `Просрочено на 2 дня`.
Состояния: `none` (чипа нет) · `empty` (пунктирный чип «Срок» — в `TaskEditor` всегда, в строке на десктопе только при hover/focus-within, чтобы не шуметь) · `set` · `due-today` (цвет `--color-text-primary`, вес 550) · `overdue` (`--color-overdue` + иконка часов + словесная подпись) · `invalid`.
Пикер: нативный `input[type=date]` плюс быстрые пресеты «Сегодня / Завтра / Через неделю / Убрать срок». Нативный инпут выбран сознательно: бесплатно даёт мобильную клавиатуру, локаль и доступность.
Интерактивность и быстрый путь — ровно по той же таблице, что у `PriorityChip` выше, включая мобильный `static`. Выбор применяется сразу и объявляется в `LiveRegion` («Срок: завтра, 21 октября»).

### 3.14 `DragHandle`
Иконка 20 px, зона нажатия 32×32 десктоп, 44×44 мобайл. `cursor: grab` → `grabbing`.
Это **кнопка** с `aria-label` «Переместить задачу: {название}» и полноценным клавиатурным режимом (см. 6.4).

### 3.15 `Menu`
Пункты: `Изменить`, `Удалить` (вариант `danger`). Открытие по `more`.
`Изменить` открывает `TaskEditor` (3.11a) — то есть правку текста, приоритета и срока, а не только текста. Отдельных пунктов «Приоритет» и «Срок» в меню нет: подменю ради двух полей, которые и так видны в редакторе, — лишний уровень (Hick's Law).
Поведение: фокус уходит в первый пункт, ↑/↓ навигация, `Esc` закрывает и **возвращает фокус на кнопку**, клик снаружи закрывает. `role="menu"` / `menuitem`.

### 3.16 `ConfirmDialog`
Один сценарий: «Удалить все выполненные (N)?». Размер `md` 480 px, `--radius-xl`, подложка `rgba(3,3,10,.55)`.
Кнопки: `danger` «Удалить N задач» + `secondary` «Отмена». Фокус при открытии — на «Отмена» (безопасный выбор по умолчанию). Фокус-ловушка, `Esc` закрывает, после закрытия фокус возвращается на источник.
Формулировки нейтральные: никакого «Нет, я передумаю» и прочего пристыживания.

### 3.17 `Toast`
Варианты: `info`, `success`, `danger`. Позиция: десктоп — правый нижний угол, мобайл — на всю ширину над `Fab`.
Живёт 6 с, таймер **ставится на паузу** при наведении и при фокусе внутри. Максимум 3 в стопке, старые вытесняются. Кнопка действия — `Button sm primary`.
Доступность: `role="status"` для info/success, `role="alert"` для danger.
Поверхность: фон `--color-surface-2`, граница `--color-surface-border-strong`, тень `--shadow-lg`, `backdrop-filter: blur(var(--blur-surface))`. Корневой элемент обязан нести класс `.toast` — через него срабатывает обязательный фолбэк 2.7 (`--color-surface-2-solid`). Без фолбэка текст списка просвечивает сквозь тост, а тост — единственное место, где живёт «Вернуть» после удаления.

### 3.18 `EmptyState`
Варианты: `first-run` · `no-active` · `no-completed` · `no-search-results`.
Состав: круглая арт-подложка 88 px, заголовок `text-h2`, текст `text-body` шириной до 30 символов строки, 1–2 действия, у `first-run` — ряд подсказок с `kbd`.
Тексты обязаны быть конкретными: не «Ничего не найдено», а «По запросу «контракт» нет задач. Проверьте раскладку или сбросьте фильтр «Активные»» + кнопка «Искать во всех».

### 3.19 `Skeleton`
Строка 56 px, `--radius-lg`, shimmer 1.4 s linear. Показывается **только если гидратация дольше 120 мс**; быстрее — сразу контент, без мигания. На списке `aria-busy="true"`.
При `prefers-reduced-motion` — статичная подложка без бегущего блика.

### 3.20 `ProgressRing`
Кольцо 44 px, обводка 4 px, заливка `--gradient-accent`, рядом «3/7» и подпись «готово».
Доступность: `role="img"` с `aria-label` «Выполнено 3 из 7 задач». Числа дублируются текстом — кольцо не единственный носитель.

### 3.21 `ErrorBanner`
Живёт над списком, список остаётся рабочим. Иконка, заголовок, объяснение простым языком, 1–2 действия.
`role="alert"`. Сценарии: хранилище недоступно (приватный режим), квота исчерпана, данные повреждены.

### 3.22 `Tooltip`
Задержка появления 400 мс, исчезает мгновенно. **Никогда** не единственный источник информации — всё, что в тултипе, есть в `aria-label`.

### 3.23 `ShortcutsSheet`
Модал со списком горячих клавиш, открывается по `?`. Содержимое — таблица 2 колонки.

### 3.24 `Fab` (только мобайл)
56×56, `--gradient-accent`, иконка `+`. Правый нижний угол, отступ `--space-5` + `env(safe-area-inset-bottom)`. Открывает bottom sheet `Composer` с автофокусом в поле.

### 3.25 `LiveRegion`
Невидимый `div` с `aria-live="polite"` и `aria-atomic="true"`. Через него проходят: число результатов поиска, смена фильтра, перемещение при клавиатурном drag, удаление и отмена, смена темы.

## 4. Экраны и состояния

Везде ниже «десктоп» = 1440×900, «мобайл» = 390×844.

### S1 · Главный экран, есть задачи
Сверху вниз: header → эйбрау с датой → `Сегодня` (`text-display`) → подзаголовок со сводкой → `ProgressRing` справа → `Composer` → sticky-тулбар (`SearchField` + `SegmentedControl`) → список → секция `Выполнено`.
Sticky-полоса тулбара **прозрачна, пока список не уехал под неё**; по `IntersectionObserver` добавляется `.is-stuck` → полупрозрачный холст + blur 16 px + маска-растушёвка снизу 12 px. Без этого на цветном фоне получается грязный прямоугольник.
Скриншоты: `a-dark-1440.png`, `a-light-1440.png`.

### S2 · Первый запуск, пусто
`Composer` остаётся на месте и активен, вместо списка — `EmptyState first-run`: «Пока пусто» / «Запишите первую задачу — остальное подхватится по ходу дела» / кнопка «Добавить задачу» (ставит фокус в `Composer`) / ряд подсказок `N` · `/` · `?`.
Тулбар со счётчиками и секция `Выполнено` скрыты целиком — пустые фильтры в пустом приложении это шум.
Скриншот: `a-states-dark-1440.png`, ячейка 1.

### S3 · Загрузка
Скелет: заголовок 34 px, тулбар 40 px, 4 строки по 56 px с убыванием прозрачности (1 / .75 / .5 / .3). Появляется только при гидратации >120 мс.
Скриншот: `a-states-dark-1440.png`, ячейка 4.

### S4 · Поиск
Активный `SearchField`, список отфильтрован, совпадения в `<mark>`. В `LiveRegion` — «Найдено N задач».
Ноль результатов → `EmptyState no-search-results` с текстом запроса, кнопками «Очистить поиск» и «Искать во всех» (последняя появляется, только если активен фильтр, кроме «Все»).
Скриншот: `a-states-dark-1440.png`, ячейка 2.

### S5 · Фильтры
`Активные` — без секции `Выполнено`. `Готовые` — только секция выполненных, `Composer` остаётся (можно добавить задачу, она уедет в активные, и об этом сообщает тост «Задача добавлена в «Активные»» — иначе пользователь решит, что ничего не произошло).
Пустой фильтр `Готовые` → `EmptyState no-completed`. Пустой `Активные` при непустом списке → `no-active` с поздравительной формулировкой без сюсюканья.

### S6 · Правка задачи *(дополнено в v1.1)*
Строка превращается в `TaskEditor` (3.11a): `textarea` с авторостом, под ней ряд полей — чип приоритета и чип срока, — ещё ниже `Сохранить` / `Отмена` и подсказка `Enter сохранить · Esc отмена`. Граница — `--shadow-glow-accent`. Текст виден целиком, без обрезки.
Правятся **все три поля**: текст, приоритет, срок. Приоритет и срок меняются внутри редактора теми же `PrioritySelect` и `DueDatePicker`, что в `Composer`, и применяются по «Сохранить» вместе с текстом; «Отмена» откатывает все три.
`Enter` сохраняет (только пока фокус в `textarea` — когда открыт попап приоритета или срока, `Enter` выбирает пункт), `Shift+Enter` — перенос, `Esc` отменяет (при открытом попапе первый `Esc` закрывает попап, второй — редактор), клик снаружи сохраняет (Postel's Law: не теряем работу пользователя). Пустой результат = отмена, а не удаление.
Быстрый путь без входа в правку (только десктоп): клик по чипу приоритета или срока прямо в строке открывает тот же попап и применяет значение сразу. На мобайле чипы в строке не интерактивны — правка через лист. Обоснование и таблица — в 3.12.
Скриншоты: `edit-dark-1440.png`, `edit-light-1440.png`, `edit-dark-390.png`; исходник `concept-a-edit.html`.

### S7 · Удаление и отмена
Строка схлопывается, появляется `Toast danger` «Задача удалена: «…»» с кнопкой «Вернуть». 6 с, пауза на hover/focus. `Ctrl/Cmd+Z` возвращает последнюю удалённую задачу **на её прежнюю позицию** и работает до следующего изменения списка.

### S8 · Drag & drop
Поднятая строка: `--shadow-drag`, `scale(1.015)`, `rotate(-.6deg)`, граница `--color-accent`, фон становится непрозрачным (`--color-surface-2-solid`) — полупрозрачная карточка в полёте читается грязно.
Место вставки: пунктирная рамка 1.5 px `--color-accent-text` + подложка `--gradient-accent-soft`, высота равна высоте перетаскиваемой строки.
После отпускания — FLIP-переукладка соседей.

### S9 · Ошибка хранилища
`ErrorBanner` над списком: «Не удаётся сохранить изменения» / «Браузер заблокировал локальное хранилище — скорее всего, включён приватный режим. Задачи в этой вкладке работают, но после закрытия пропадут.» / «Повторить» + «Выгрузить в файл».
Список остаётся полностью рабочим в памяти.
Скриншот: `a-states-dark-1440.png`, ячейка 5.

### S10 · Длинный контент
Заголовок до 500 символов: 2 строки + чип «Показать целиком» → раскрытие на всю высоту + чип «Свернуть». 100+ задач: виртуализации нет (не нужна на таком объёме), но sticky-тулбар и секции обязаны оставаться на месте.
Скриншот: `a-states-dark-1440.png`, ячейка 6.

### S11 · Мобайл
Герой в колонку, `ProgressRing` под подзаголовком слева. `Composer` скрыт → `Fab`. Тулбар в две строки: поиск, под ним сегменты во всю ширину. Строки выше (64), handle виден всегда, действия — по долгому нажатию.
Скриншоты: `a-dark-390.png`, `a-light-390.png`.

### S12 · Горячие клавиши
Модал по `?`. Полный список — в разделе 6.3.

## 6. Поведение по вьюпортам

### 6.1 Desktop 1440×900
Колонка 760 px по центру (текст `364…1076`, см. 2.9), гаттеры `--space-6`, шапка выровнена по той же колонке (3.3), сияние занимает весь экран за колонкой. Строка 56 px. Действия строки — по hover. Тост в правом нижнем углу. Брейкпоинт — `640px`, он единственный (контент-driven: ниже 640 колонка перестаёт держать две строки меты в ряд).

### 6.2 Mobile 390×844
Правка задачи — bottom sheet `TaskEditor`, а не инлайн-редактор: инлайн при открытой клавиатуре съедает экран и уводит поля под неё. Чипы в строке — `static`.
Гаттеры `--space-4` (текст `16…374`), строка 64 px, верхний отступ контента `--space-5`, нижний 120 px (под `Fab` и тост). Колонка здесь уже окна, поэтому выравнивание шапки по колонке на мобайле ничего не двигает: вордмарк и так на `x = 16`. `Composer` → `Fab` + bottom sheet. Сегменты растягиваются на равные доли и скроллятся горизонтально при переполнении. Все цели ≥44×44. Зона большого пальца: `Fab` и действия тоста — в нижней трети экрана; деструктивных кнопок там нет.

### 6.3 Горячие клавиши
`N` новая задача · `/` фокус в поиск · `1` `2` `3` фильтры · `?` шпаргалка · `Esc` закрыть/отменить/очистить · `↑` `↓` переход между строками · `Space` отметить выполненной · `E` править (текст, приоритет и срок) · `Delete` / `Backspace` удалить · `Ctrl/Cmd+Z` вернуть удалённую · `Ctrl/Cmd+↑` `↓` переместить строку на шаг.
Отдельных горячих клавиш на приоритет и срок нет сознательно: буквы в этом приложении и так заняты, а скрытые сочетания без видимого носителя — это recall вместо recognition. Оба поля лежат в редакторе на расстоянии одного `E`.

### 6.4 Клавиатурный drag & drop (обязателен)
Фокус на `DragHandle` → `Space` «поднимает» строку (`aria-grabbed="true"`, объявление «Задача «X» поднята, позиция 3 из 7») → `↑`/`↓` двигают с объявлением новой позиции → `Space` опускает («опущена на позицию 2») → `Esc` отменяет («перемещение отменено, позиция 3»).
Альтернатива без режима: `Ctrl/Cmd+↑/↓` на сфокусированной строке двигают её на шаг сразу.
Мышиный drag без клавиатурной альтернативы — не принимается.

## 7. Доступность

**Фокус.** `outline: 2px solid var(--color-focus-ring); outline-offset: 2px` на всех интерактивных элементах. `outline: none` без замены запрещён. Кольцо не анимируется.

**Порядок фокуса.** header → `Composer` (поле → приоритет → срок → `+`) → `SearchField` → `SegmentedControl` (одна остановка, внутри ←/→) → список (одна остановка, внутри ↑/↓) → секция `Выполнено` → модалы поверх с ловушкой фокуса.
Внутри списка — roving tabindex: строка является узлом навигации; кнопки `edit`/`more`/`handle` и интерактивные чипы приоритета и срока получают `tabindex="0"` только пока их строка в фокусе, иначе `-1`. Иначе на 20 задачах получается 80+ остановок Tab.
Внутри `TaskEditor` порядок: `textarea` → чип приоритета → чип срока → `Сохранить` → `Отмена`. Пока редактор открыт, фокус из него не выпадает по Tab (мягкая ловушка: с «Отмена» Tab возвращает в `textarea`) — иначе пользователь уезжает в список с несохранёнными правками. Попапы приоритета и срока — вложенные, со своей ловушкой и возвратом фокуса на чип по `Esc`.

**Контраст.** Весь текст ≥4.5:1 (значения в разделе 2). Граница чекбокса ≥3:1 через `--color-control-border`.
Почему остальные границы слабее 3:1 и это допустимо: инпуты, кнопки и сегменты опознаются не контуром, а собственной заливкой поверхности, иконкой и плейсхолдером — контур у них декоративный. У чекбокса контур — единственный признак, поэтому там отдельный токен. Это осознанное решение, а не упущение.

**Независимость от цвета.** Приоритет = глиф + цвет + подпись. Просрочка = иконка часов + слова «Просрочено на N дн.». Выполненное = галочка + зачёркивание + приглушение. Нигде цвет не единственный канал.

**Размеры целей.** Мобайл ≥44×44. Десктоп ≥32×32 с зазором ≥8 px между соседними целями. Минимум WCAG 2.2 (24×24) выполняется везде, включая чип приоритета: в интерактивном варианте его высота ровно 24 px, поэтому уменьшать её нельзя. На мобайле чипы в строке не интерактивны именно потому, что до 44×44 там не дотянуть (см. 3.12); в листе правки те же значения стоят на строках 48 px. Кнопки добирают 44 px собственной высотой, а не зазором: `Button` любого размера на мобайле ≥44 (см. 3.5). На десктопе высоты возвращаются к 32 / 40 / 48 — плотность диалогов и панелей там не меняется.

**Таймауты.** Единственный таймер — тост 6 с. Он останавливается при наведении и при фокусе внутри, и то же действие доступно через `Ctrl/Cmd+Z`. Существенных ограничений по времени нет.

**Объявления.** `LiveRegion` (`aria-live="polite"`) на: результаты поиска, смену фильтра, добавление/удаление/возврат, все шаги клавиатурного перемещения, смену темы, смену приоритета и срока («Приоритет: средний», «Срок: завтра, 21 октября», «Срок убран»), сохранение и отмену правки. `ErrorBanner` — `role="alert"`.

**Семантика.** Список — `ul`/`li`. Фильтры — `tablist`/`tab`/`tabpanel`. Чекбокс — нативный `input`, визуально скрытый, с доступным именем из текста задачи. Модалы — `role="dialog"` + `aria-modal="true"` + `aria-labelledby`. Иконочные кнопки — с `aria-label`.

**Язык и текст.** `lang="ru"`. Тексты простые, без терминов. Ошибки говорят, что произошло и что сделать, а не код.

**Движение.** `prefers-reduced-motion` обрабатывается по таблице раздела 5; дрейф сияния отключается полностью.

**Масштабирование.** 200 % зума и `font-size: 200%` не должны ломать вёрстку: колонка и строки на `rem`/токенах, фиксированных высот текста нет.

## 8. Критерии приёмки

Проверяемо, по пунктам. QA гоняет на 1440×900 и 390×844, в светлой и тёмной теме.

**Токены**
1. В CSS нет цветов, отступов, радиусов, теней и длительностей вне токенов (проверяется grep по хардкоду `#`, `px` вне слоя токенов).
2. Обе темы переключаются сменой `data-theme` на `<html>` без перезагрузки и без вспышки белого при старте.
3. Автотест контраста прогоняет все пары из таблиц 2.1–2.2 и падает при <4.5:1 для текста и <3:1 для `--color-control-border`.

**Функциональность**
4. Задача добавляется по `Enter`; фокус остаётся в поле; чипы приоритета и срока сброшены.
5. Правка открывается по `E`, двойному клику, кнопке `edit` и пункту `Изменить`; в редакторе доступны текст, приоритет и срок; `Enter` сохраняет, `Esc` отменяет, клик снаружи сохраняет; пустой текст = отмена, не удаление.
6. Удаление показывает тост с «Вернуть» на 6 с; возврат ставит задачу на прежнюю позицию; `Ctrl/Cmd+Z` делает то же.
7. Отметка выполненной: анимация 240 мс, затем переезд в `Выполнено` через 600 мс; снятие возвращает на прежнее место в активных.
8. Фильтры и поиск работают совместно; счётчики сегментов совпадают с фактическим числом.
9. Порядок после drag & drop сохраняется в `localStorage` и переживает перезагрузку.
10. «Удалить все выполненные» спрашивает подтверждение с числом; «Отмена» ничего не меняет.

**Состояния**
11. Все четыре варианта `EmptyState` достижимы и показывают предписанные тексты и кнопки.
12. Скелет появляется только при гидратации >120 мс и не мигает при быстрой загрузке.
13. В приватном режиме (или при заблокированном `localStorage`) показывается `ErrorBanner`, приложение остаётся рабочим.
14. Задача на 500 символов обрезается в 2 строки (мобайл 3) и раскрывается по чипу; вёрстка не разъезжается.
15. При 100 задачах sticky-тулбар не дёргается, страница скроллится плавно.

**Движение**
16. Каждая анимация совпадает с таблицей раздела 5 по длительности и easing.
17. При `prefers-reduced-motion: reduce` дрейф сияния остановлен, трансформаций нет, остаётся только `opacity`; ни одно действие не становится недоступным.
18. Отклик на ввод (hover, focus, нажатие) — не дольше 140 мс.

**Адаптив**
19. На 390×844 нет горизонтального скролла; все цели ≥44×44; `Fab` не перекрывает последнюю строку списка.
20. На 1440×900 колонка 760 px по центру (бокс `340…1100`, текст `364…1076`); sticky-полоса тулбара прозрачна до скролла и проявляется после.
21. Единственный брейкпоинт — 640 px; между 390 и 1440 нет состояний со сломанной вёрсткой.

**Доступность**
22. Весь сценарий — добавить, найти, отфильтровать, отредактировать, переместить, выполнить, удалить, вернуть — проходится только с клавиатуры.
23. Клавиатурное перемещение работает по разделу 6.4 и озвучивает каждый шаг.
24. Кольцо фокуса видно на каждом интерактивном элементе в обеих темах.
25. Скринридер (VoiceOver или NVDA) читает строку как «флажок, не отмечен, {текст задачи}, приоритет высокий, просрочено на 2 дня».
26. Отключение цвета (grayscale-фильтр) не мешает отличить приоритеты и просрочку.
27. Зум 200 % не ломает вёрстку и не прячет контент.
28. axe-core или аналог на главном экране — ноль нарушений уровня critical и serious.

**Правка приоритета и срока** *(добавлено в v1.1; нумерация 1–28 не сдвинута намеренно, на неё уже ссылается тест-план FELA-5)*
29. У существующей задачи меняются приоритет и срок, и это переживает перезагрузку. Путь через `TaskEditor` работает на обоих вьюпортах; «Отмена» откатывает все три поля разом, включая приоритет и срок.
30. На десктопе клик по чипу приоритета или срока в строке открывает тот же попап и применяет значение сразу, без «Сохранить»; изменение озвучивается в `LiveRegion`.
31. На 390×844 чипы в строке не кликабельны и не фокусируемы; правка приоритета и срока доступна через лист `TaskEditor`, все его цели ≥44×44.
32. Весь путь «открыть правку → сменить приоритет → сменить срок → сохранить» проходится с клавиатуры: Tab не выпадает из открытого редактора, `Esc` закрывает сначала попап, потом редактор, фокус возвращается на строку.
33. Сегменты фильтра при счётчике 0 остаются кликабельными и фокусируемыми; `disabled` и `aria-disabled` на них отсутствуют (проверяется в DOM).

**Выравнивание шапки** *(добавлено в v1.3)*
34. На 1440×900 `getBoundingClientRect().left` у вордмарка равен `left` у `h1` «Сегодня» (364), а `right` у внешней `IconButton` в шапке равен `right` текстовой области `main` (1076). На 390×844 — 16 и 374. Расхождение 0 px, проверяется числами, а не глазом. У `header` при этом нет ни `background`, ни `border-bottom`, ни `position: sticky`.

**Вес моноширинного текста** *(добавлено в v1.4)*
35. У каждого элемента, у которого `font-family` разрешается в `--font-mono` (счётчики сегментов, счётчик символов `Composer`, `kbd`), вычисленный `font-weight` равен `400`, а `font-variant-numeric` содержит `tabular-nums` — проверяется через `getComputedStyle`, а не на глаз. Веса `text-caption` / `text-label` / `text-micro` при этом остаются 500 / 550 / 600 для Inter.

36. Блок 2.7 и код сходятся в обе стороны. Первое: для каждого селектора из блока `@supports not (backdrop-filter: …)` в собранном DOM есть хотя бы один подходящий элемент — мёртвых крючков нет. Второе: у каждого элемента, у которого вычисленный `backdrop-filter` не равен `none`, есть непрозрачная подложка в этом блоке — забытых поверхностей нет. Проверяется перечислением по собранному CSS и реальному DOM, а не в jsdom: там `@supports` и `backdrop-filter` не разрешаются и тест будет зелёным впустую. Подложка берётся того же уровня, что и полупрозрачный фон: `Toast` → `--color-surface-2-solid`, остальные — `--color-surface-1-solid`.

37. На 390×844 высота `Button` равна 44 при `size="sm"` и `size="md"` и 48 при `size="lg"`; на 1440×900 — 32, 40 и 48. Меряется `getBoundingClientRect().height` в собранном `dist` в реальном браузере, а не в jsdom. Контрольная поверхность — `ConfirmDialog` (3.16): обе его кнопки `md`, и на телефоне это единственный путь подтвердить и отменить массовое удаление.

## 9. Что осознанно **не** делаем

Фиксирую, чтобы не всплыло как «забыли».

- Нет времени у срока — только дата.
- Нет категорий, тегов, проектов, подзадач, повторов, напоминаний.
- Нет виртуализации списка — не нужна на ожидаемом объёме.
- Нет анимированных иллюстраций в `EmptyState` — статичная арт-подложка.
- Нет мультивыбора и групповых действий, кроме «удалить все выполненные».
- Нет автосортировок — порядок только ручной.
- Не берём переменный JetBrains Mono *(решение FELA-46)*. Моно в продукте — это три счётчика фильтров, счётчик символов и `kbd`; ни одному из них не нужен вес, кроме 400. Вес на оси понадобился бы только ради того, чтобы токен формально совпал с числом в таблице, — это не польза для пользователя, а лишние килобайты в бюджете шрифтов.
